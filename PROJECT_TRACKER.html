المهمة الحالية الآن

Milestone 1 - الخطوة 1.1: تصميم جدول المواقع في Supabase

الهدف: إنشاء جدول خفيف في PostgreSQL مخصص لتخزين آخر موقع لكل جهاز مع دعم الـ Upsert والتحديث اللحظي الفوري.

💡 فكرة التصميم: لا تقم بعمل `INSERT` جديد لكل تحرك، لأن ذلك سيملأ قاعدة البيانات بملايين السجلات بسرعة! سنصمم صفاً واحداً لكل مستخدم يتم تحديثه دائماً (`UPSERT`).

هيكل الـ SQL الاسترشادي (الهيكل البنائي المطلوب منك إكماله):

-- 1. جدول المواقع الحية CREATE TABLE public.locations ( id UUID DEFAULT gen_random_uuid() PRIMARY KEY, user_id TEXT UNIQUE NOT NULL, -- مفتاح فريد لكل جهاز/مستخدم لتسهيل الـ Upsert latitude DOUBLE PRECISION NOT NULL, -- خط العرض بدقة عائمة مزدوجة longitude DOUBLE PRECISION NOT NULL, -- خط الطول heading DOUBLE PRECISION DEFAULT 0.0, -- زاوية التوجيه (0-360) للماركر speed DOUBLE PRECISION DEFAULT 0.0, -- السرعة الحالية (م/ث أو كم/س) updated_at TIMESTAMPTZ DEFAULT now() -- توقيت آخر تحديث );
⚠️ تحذير تقني (Gotcha): تأكد من وضع UNIQUE على user_id، لأن مكتبة Supabase في فلاتر عندما تستخدم upsert() تحتاج لعمود فريد (onConflict) لتعرف هل تقوم بالتعديل (Update) أم الإضافة (Insert).

مفاهيم سريعة في Supabase

ما هو Supabase؟ عبارة عن قاعدة بيانات PostgreSQL سحابية مضافاً إليها محرك WebSockets جاهز (Realtime Engine) وواجهات REST تلقائية.

الـ Realtime: بدلاً من أن تقوم بعمل Polling (طلب الموقع كل ثانية من السيرفر)، السيرفر نفسه هو من يرسل التحديث للموبايل بمجرد تغير الصف في قاعدة البيانات عبر WebSocket خفيف وسريع.
